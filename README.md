# Вопрос на вечер

Статический русскоязычный сайт спокойной интеллектуальной игры. В demo-режиме содержит **31 оригинальный демонстрационный вопрос**: вопрос даты запуска и 30 предыдущих дат. Вопросы не приписаны телевизионным или спортивным играм.

## Быстрый запуск

Требуется Node.js 22+.

```bash
cp .env.example .env
npm ci
npm run dev
```

Production-проверка: `npm run build`, затем `npm run preview`. Тесты: `npm test` и после build `npm run test:e2e`. Service Worker полноценно проверяется через production preview на localhost либо HTTPS, а не через dev-сервер.

Даты seed зафиксированы в репозитории и обычная сборка их не перераспределяет. Для осознанного сброса: `LAUNCH_DATE=2026-09-05 npm run demo:reset`. Затем закоммитьте изменённые публичные данные.

## Архитектура и данные

Astro заранее создаёт `/`, `/archive/` и постоянные страницы дат. Публичные JSON лежат в `data/public`, а публикация атомарно готовит `public/content.next`, валидирует данные и только затем переименовывает каталог, сохраняя `content.previous`. Редакционное состояние (`data/editorial`) должно храниться в **закрытом долговечном репозитории/ветке**; оно не должно попадать в публичный deployment artifact.

В браузере Cache Storage хранит оболочку и данные, IndexedDB (`progress`, `questions`, `manifest`) отделён от кеша, а localStorage — деградированный резерв прогресса. После синхронизации сохраняются текущий и 30 последних вопросов с ограничением в три параллельных запроса. Черновики никуда не отправляются. Ответы входят в опубликованные JSON для честной офлайн-работы и не обфусцируются.

## Контентный pipeline и CLI

`SourceAdapter` и JSON-адаптер находятся в `scripts/core.ts`. Fixture запускается командой `npm run pipeline`. HTTP-источник намеренно заблокирован: владелец ещё не предоставил проверенный источник, схему данных и документированное разрешение на перепубликацию. Публичная доступность страницы разрешением не считается. Подготовка через LLM также не вызывает внешний сервис без явного провайдера; содержимое источника трактуется только как данные.

```bash
npm run content -- review
npm run content -- reserve
npm run content -- approve RECORD_ID
npm run content -- reject RECORD_ID
npm run content -- retry RECORD_ID
npm run content -- edit RECORD_ID '{"text":"Исправленный текст"}'
npm run content -- revoke RECORD_ID
npm run publish
```

После `edit` запись возвращается в `validated` для повторной проверки. Цель резерва — 30 approved, предупреждение начинается ниже 7. Публикация берёт только approved/scheduled записи; при пустом резерве ничего не повторяет. Checkpoint, отчёт и статусы сохраняются. CI concurrency исключает штатные конкурентные публикации; перед фиксацией скрипт проверяет уникальность id/даты. Для восстановления верните `public/content.previous` или предыдущий Git-коммит и пересоберите сайт.

`ALERT_WEBHOOK_URL` — опциональная будущая точка интеграции. Текущая реализация **не отправляет** сообщения: она пишет дедуплицируемый структурированный `last-report.json`, поэтому нельзя считать webhook подключённым.

## Конфигурация и безопасность

Все переменные перечислены в `.env.example`. `SITE_URL`, `TIMEZONE` (`Europe/Moscow`), `CONTENT_MODE`, `LAUNCH_DATE`, `DONATION_URL` относятся к сборке. Донат показывается только для корректного HTTPS URL и открывается внешне. `SOURCE_*`, `RIGHTS_BASIS`, `LLM_*`, лимиты и `ALERT_WEBHOOK_URL` — только закрытая фоновая среда, без префикса `PUBLIC_`.

Исходящие URL должны быть HTTPS; до реализации HTTP-адаптера также следует запретить private/loopback IP, ограничить redirects, размер ответа, timeout, частоту и retries. Никогда не исполняйте текст источника как команды. Production build с `CONTENT_MODE=production` отклоняет `isDemo`. Заголовки Netlify задают CSP, запрет framing и revalidation манифеста/SW.

Локальный бюджет резервирует оценочный максимум перед подготовкой и учитывает фактический usage, но **не гарантирует** счёт провайдера. Дополнительно настройте hard spending limit/alerts в кабинете выбранного провайдера, если он это поддерживает.

## Размещение и расписание

Поддерживаемый пример — Netlify для статического `dist` (`netlify.toml`); подключите собственный репозиторий и домен, build command `npm run build`. GitHub Actions workflow запускается в 21:10 UTC (00:10 Москвы) и допускает ручной повтор. Файл workflow — лишь конфигурация: расписание не активно, пока репозиторий не размещён и Actions не включены. Состояние pipeline должно коммититься в закрытую ветку/репозиторий, затем разрешённая публичная проекция передаётся в публичную сборку. Не храните секреты в Git.

### Параметрическая оценка расходов

Актуальные тарифы намеренно не заявлены: их надо проверить в день запуска.

| Статья | Формула в месяц |
|---|---|
| Статический хостинг/трафик | тариф хостинга + превышение включённого трафика |
| CI/расписание | минуты `daily checks + публикации + retries` × цена минуты сверх квоты |
| LLM | `(31 + первичный резерв 30 + замены) × попытки × (input tokens × input price + output tokens × output price)` |
| Домен | годовая цена / 12, отдельно |

Плановые 2000–2500 ₽ — ограничение выбора, не подтверждённая стоимость. Перед подключением подставьте реальные цены, курс, worst-case `LLM_MAX_ATTEMPTS`, `LLM_MAX_TOKENS` и `MAX_NEW_PER_RUN`.

## Выход в production — действия владельца

1. Получить документированное право на повторную публикацию, зафиксировать источник и основание; подготовить реальный стартовый набор.
2. Реализовать/включить HTTP adapter только под подтверждённую схему и сетевые ограничения; выбрать LLM, ключ, модель и жёсткий provider budget.
3. Проверить review-очередь вручную, сформировать резерв 30 и собрать с `CONTENT_MODE=production`.
4. Указать `SITE_URL`, включить Netlify HTTPS и GitHub Actions с долговечным закрытым editorial state.
5. При желании указать реальный HTTPS `DONATION_URL`; без него ссылка отсутствует.
6. Провести offline и accessibility smoke-test на целевых телефонах, настроить резервное копирование и процедуру отзыва.

Главный блокер полностью автоматического production-наполнения: нет предоставленного и юридически подтверждённого источника с согласованной схемой/правами, а также выбранного и настроенного LLM-провайдера. Демо, локальная сборка и fixture pipeline не означают публичный деплой или подключение источника.
